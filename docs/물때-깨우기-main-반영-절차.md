# 깃허브 「물때 깨우기」를 main 에 넣는 절차

## ★ 끝났습니다 (2026-10-14)

주인 승인 「그래 진행하자」를 받아 **main 에 넣고 켰습니다.**

```
main  598931c → a66ea0b   물때 깨우기 일꾼을 켭니다
```

아래는 **그때 밟은 차례**입니다. 다시 할 일이 있을 때 보십시오
(예: 끄기·되돌리기·다른 일꾼을 같은 식으로 올리기).

---

## 왜 main 에 넣어야 하나

깃허브는 **기본 가지(main)에 있는 워크플로의 정기 실행(schedule)만**
돌립니다. 작업 가지에만 있으면 주석을 풀어도 **아무 일도
일어나지 않습니다.**

넣을 파일은 **하나뿐**입니다 — `.github/workflows/tide-poke.yml`
(주소 하나를 두드릴 뿐이고 비밀값이 필요 없습니다)

---

## ★ 먼저 알아야 할 것 — 로컬 main 이 **뒤처져 있습니다**

2026-10-14 확인:

```
로컬  main        0f860b3  어종 카드 사진을 자르지 않습니다
원격  origin/main 598931c
```

**다릅니다.** 그리고 `598931c` 는 보존 사항에 적힌
**출처 불명 4커밋**(`e344027`·`6977508`·`f781212`·`598931c`) 중
하나입니다.

- 그 커밋들은 **원격 main 에 이미 들어가 있습니다.**
  (보존 사항은 「**작업 가지**에 섞지 말 것」이므로, main 에서만
   다루는 것은 그 규칙을 어기지 않습니다)
- 그러나 **로컬 main 이 뒤처져 있어** 그대로 밀면
  거부되거나 엉뚱한 것이 올라갑니다.

⇒ **먼저 맞춘 뒤**에 파일을 얹어야 합니다.

---

## 차례

```bash
cd "D:/바다가자/두번째도전"

# ① 지금 가지를 적어 둡니다 (돌아올 곳)
git branch --show-current          # 물때접힘-20261014

# ② 작업물이 모두 커밋되어 있는지 — 비어 있어야 합니다
git status --short

# ③ 원격을 받아 옵니다
git fetch origin

# ④ main 으로 가서 원격에 맞춥니다
git checkout main
git merge --ff-only origin/main
#   ★ 여기서 막히면(갈라졌으면) **멈추고 감독실에 알립니다.**
#     억지로 병합하지 않습니다 — 출처 불명 커밋이 섞일 수 있습니다.

# ⑤ 워크플로 파일 **하나만** 가져옵니다 (병합이 아닙니다)
git checkout 물때접힘-20261014 -- .github/workflows/tide-poke.yml

# ⑥ 들어온 것이 그 하나뿐인지 **반드시 봅니다**
git status --short
#   .github/workflows/tide-poke.yml 한 줄만 나와야 합니다

# ⑦ 정기 실행 주석을 풉니다 (승인된 때에만)
#   tide-poke.yml 의 `#   schedule:` 두 줄에서 `#` 를 뗍니다

# ⑧ 커밋
git add .github/workflows/tide-poke.yml
git commit -m "물때 깨우기 일꾼을 켭니다 (주인 승인)"

# ⑨ 푸시 — ★ 감독실이 확인한 뒤에
git push origin main

# ⑩ 작업 가지로 돌아옵니다
git checkout 물때접힘-20261014
```

---

## 켠 뒤 확인

1. 깃허브 Actions 에 「물때 깨우기」가 보이는지
2. 손으로 한 번 돌려(`Run workflow`) 끝까지 가는지
3. 마지막 단계의 상태 출력에 `전체` 수치가 보이는지
4. 다음 정해진 때(네 시간마다)에 저절로 도는지

---

## 끄려면

`tide-poke.yml` 의 `schedule:` 두 줄을 **다시 주석 처리**하고
푸시하면 됩니다. 또는 깃허브 Actions 화면에서 그 워크플로를
**Disable** 합니다.

★ 끄더라도 **손님이 올 때의 자동 갱신은 그대로 돕니다.**
  이 일꾼은 「손님이 없는 밤」을 메우는 **덤**입니다.
