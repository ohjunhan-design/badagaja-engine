> 「읽기 전용 전수 대조 승인. 서버 목록 확보 → 새 배포 목록과
>  대조 → 『잔재 / 보호 대상 / 판단 불가』로 분류 →
>  **삭제 없이 보고서만.**」

**아무것도 지우지 않았습니다.** 운영 주소에 HEAD 로 찔러 보기만
했습니다. 도구는 `engine/check_server_leftover.py` 입니다.

---

## 왜 남나

**배포가 `--delete` 를 안 씁니다.** 옛 판이 올려 둔 쪽은
새 판이 안 만들어도 서버에 그대로 남습니다.

    옛 판 630쪽 · 새 판 450쪽 · 새 판에 없는 옛 쪽 207개
    그중 서버에 살아 있는 것 **11개**

나머지는 보호 대상 190개(`zh-cn/`·`api/`)와 이미 없는 것 6개입니다.
**판단 불가 0 — 207개를 모두 확인했습니다.**

## 제 의견 (실행 안 함 · 주인 결정 사항)

| 갈래 | 할 일 |
|---|---|
| ㄱ 남길 것 (3) | **그대로 둡니다.** 잔재가 아닙니다 |
| ㄴ 새 쪽이 대신 (5) | `club.html` 과 **함께 301** 로 보내는 것이 맞아 보입니다 |
| ㄷ club.html (1) | `club/support.html` 로 301 |
| ㄹ 따로 볼 것 (2) | 먼저 조사부터 — `copyright` 는 새 판에 대응 쪽이 있는지, `zh-tw` 는 지금 어디로 보내는지 |

**`.htaccess` 를 고치는 일이라 주인 규칙 27 이 걸립니다** —
한 번에 하나씩 · 올린 뒤 응답 코드 확인 · 500 이면 먼저 되돌림.
감독팀도 「주인 승인된 단독 배포일 때만」이라 했습니다.

### 301 을 넣는다면 이런 모양입니다 (안일 뿐, 안 넣었습니다)

```apache
Redirect 301 /club.html         /club/support.html
Redirect 301 /point/busan.html  /busanulsan/index.html
Redirect 301 /point/jeju.html   /jeju/index.html
Redirect 301 /jeju/festival.html /festival/index.html
```

목적지가 정말 있는지는 **넣기 전에 하나씩 확인해야** 합니다.
지금은 새 판이 아직 안 올라가 확인할 수 없습니다.
