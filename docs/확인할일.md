# 확인할 일 — 날짜가 되어야 알 수 있는 것

이 파일은 **때를 기다려야 하는 일**만 적습니다.
지금 할 수 있는 일은 여기 안 적습니다 — 바로 합니다.

---

## 1. 물때가 10월 10일에 하루 갈립니다  ★ 가장 급합니다

**언제 확인하나** — 2026년 10월 4일 무렵
(국립해양조사원이 이레치를 주므로, 그때쯤 10월 10일이 나옵니다)

**무엇이 문제인가**

| 날짜 | 독립 셈 | tide.js | |
|---|---|---|---|
| 10월 9일 | 음력 29일 | 음력 29일 | 같음 |
| **10월 10일** | **음력 30일** | **음력 1일** | **갈립니다** |
| 10월 12일 | 음력 2일 | 음력 3일 | 갈립니다 |

음력 8월이 **30일까지 있느냐(큰달), 29일에서 끝나느냐(작은달)**의
차이입니다. 삭(그믐)이 10월 11일 0시 무렵이라 하루로 갈립니다.

**어떻게 확인하나**

```bash
python engine/check_tide.py
```

[1] 단계가 해양조사원 값과 견줍니다. 10월 4일쯤이면 10월 10일이
그 이레 안에 들어와 어느 쪽이 맞는지 판가름됩니다.

**어느 쪽이 틀렸든 고칠 곳**
- tide.js 가 틀렸으면 → `assets/js/tide.js` 의 음력 셈
- 독립 셈이 틀렸으면 → `engine/tide_reference.py` 의 삭 시각 표
  (지금은 시(hour)만 적혀 있어 0시 언저리가 아슬아슬합니다.
   분까지 적으면 나아집니다)

**왜 급한가**
물때는 이 사이트의 뼈대입니다. 틀리면 손님이 엉뚱한 날 바다에
갑니다. **10월 10일 전에 반드시 판가름해야 합니다.**

**배포와의 관계**
이것을 확정하기 전에 배포하면, 10월 10일에 틀린 물때가 나갑니다.
배포를 미루거나, 미리 고치고 배포해야 합니다.

## 계약-01 검사에 구멍이 있습니다 (2026-09-28 찾음)

계약-01 「쪽을 만드는 곳은 하나다」는 이 두 모양만 봅니다.

    io.write...(... 나갈곳 ...)
    io.write...(os.path.join(NEW ...

그래서 `engine/mark_stage.py` 처럼

    for p in 쪽들():        # os.walk(NEW) 로 모음
        io.write(p, 새)     # ← 이 모양은 **안 잡힙니다**

배포본을 고치는 도구를 못 잡습니다.

정적으로 넓히려 해 봤더니(`os.walk(NEW)` + `io.write` 가 둘 다 있는 파일)
검사기 6개가 함께 걸립니다 — 그들은 **임시 폴더 사본**에 쓰므로 어김이 아닙니다.
글자만 봐서는 가를 수 없습니다.

**고칠 길** — 움직여 보고 잽니다.

1. `site/` 를 사본으로 뜨고 지문을 냄
2. 도구를 `BADAGAJA_SITE=사본` 으로 돌림
3. 지문이 바뀌면 그 도구가 배포본을 고친 것

느리므로 `--full` 에서만 돌립니다. 지금은 `mark_stage` 하나뿐이고
판정이 「검증판 표시가 남으면 막음」으로 지켜 주고 있으나,
**앞으로 비슷한 도구가 늘면 아무도 모르게 새어 나갑니다.**

## 서버가 막을 때 **404 를 줍니다** (2026-09-28 검증 배포에서 찾음)

카페24가 연달아 오는 요청을 막습니다. 그런데 막을 때
403 이 아니라 **404** 를 돌려줍니다.

    검사기가 본 것            실제
    about.html      404      curl 로 하나씩 치면 200
    css/style.css   404      〃
    assets/js/tide.js 404    〃

그래서 검사기가 「배포가 옛 파일을 지웠습니다」라고 말했습니다.
**없는 것과 막힌 것은 아주 다른 일인데 겉보기가 같습니다.**

사람이 쪽을 볼 때는 안 납니다 — 한 쪽씩 보니까요.
검사기만 몇십 개를 몰아치기 때문에 걸립니다.

고친 것 — `check_deployed.py` 의 `받아오기()`
- 요청 사이에 **0.4초** 틈을 둡니다
- 403·404·429·503 이면 **1.5초 쉬었다 한 번 더** 묻습니다
  (정말 없으면 쉬었다 물어도 같은 답이 옵니다. 한 번 더 묻는 값은
   싸고, 헛 FAIL 의 값은 비쌉니다)

**남은 걱정** — 416쪽을 다 재려면 0.4초 × 416 = 3분입니다.
지금은 대표 쪽만 보므로 괜찮지만, 전수로 늘리면 다시 생각해야
합니다. 서버가 어느 속도까지 견디는지 재 본 적이 없습니다.
