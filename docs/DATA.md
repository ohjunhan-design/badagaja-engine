# 자료 설계

**자료가 유일한 진실입니다.** 쪽은 자료에서 만들어지는 결과일 뿐입니다.

---

## 세 층으로 나눕니다 (계약-20)

```
data/raw/         옮기는 도구가 만듭니다. 사람이 고치지 않습니다 (덮어씁니다)
data/overrides/   사람이 고친 것만. 옮기는 도구가 절대 건드리지 않습니다
        ↓ 합침
    최종 자료      → 엔진이 씁니다 (파일로 남기지 않습니다)
```

**왜 이렇게 하나**

옛 사이트를 새 구조로 옮기는 데 몇 주가 걸립니다. 그동안 옛 사이트의 자료는
계속 바뀝니다(최근 7일에 자동 갱신 110건). 옮기는 도구를 다시 돌려야 하는데,
한 층이면 **사람이 다듬은 것이 덮어씌워집니다.**

두 층으로 나누면 옮기는 도구를 **백 번 돌려도** 손질이 살아남습니다.

**합치는 규칙**: 같은 아이디가 양쪽에 있으면 `overrides` 가 이깁니다.

---

## 아이디 — 이름을 식별자로 쓰지 않습니다

이름은 바뀝니다. 「○○방파제」가 「○○항 방파제」가 되어도 링크·사진·통계가
안 깨지려면 **바뀌지 않는 아이디**가 있어야 합니다.

| 무엇 | 꼴 | 보기 |
|---|---|---|
| 권역 | `<권역>` | `taean` · `yeosu` |
| 묶음 | `<묶음>` | `chungnam` · `jeonnam` |
| 포인트 | `<권역>-<갈래>-<번호>` | `taean-f-001` · `yeosu-g-042` |
| 축제 | `<권역>-fest-<번호>` | `wando-fest-03` |
| 명소 | `<권역>-spot-<번호>` | `taean-spot-07` |
| 어종 | `<이름표>` | `gamseongdom` · `bajirak` |
| 사진 | `photo-<다섯자리>` | `photo-00264` |

갈래 표시: `f` 낚시 · `g` 해루질

**아이디는 한 번 정하면 바뀌지 않습니다.** 옛 사이트에서 옮길 때 고정하고,
그 뒤로는 이름이 바뀌어도 그대로 둡니다.

## 폴더

```
data/
  raw/
    index.json              57권역 목록 — 모든 숫자의 기준 (계약-05)
    points/<묶음>.json      포인트 (9개 파일로 나눔)
    festivals/<묶음>.json   축제
    travel/<묶음>.json      먹거리·숙소·명소
    species.json            어종 (지역에 안 매임)
    photos.json             사진 출처
    rules.json              금어기·규정
    refresh.json            갱신 대장

  overrides/
    (raw 와 같은 모양. 고친 것만 둡니다)

  schema/
    point.json  region.json  festival.json ...   자료 모양 검사용

  cache/
    api/<이름>-<날짜>.json   바깥에서 받은 것 (계약-23)
```

**왜 묶음별로 나누나**

한 파일로 합치면 지금도 850KB, 포인트가 10,000개면 1.5MB입니다.
편집기가 느려지고 두 작업이 부딪힙니다. 나눠 두면 경남과 강원을 동시에
고쳐도 안 부딪힙니다.

**왜 더 잘게 안 나누나**

권역별로 57개 파일을 만들면 합계를 낼 때마다 57번 열어야 합니다.
묶음 9개가 알맞습니다.

## 자료 모양

### `index.json` — 모든 숫자의 기준 (계약-05)

```json
{
  "_설명": "57권역 목록. 모든 숫자는 여기서 셉니다. 손으로 적지 않습니다",
  "권역": [
    { "id": "taean",
      "이름": { "ko": "태안", "zh": "泰安" },
      "묶음": "chungnam",
      "차례": 1,
      "대표사진": "photo-00012",
      "물때관측소": { "이름": "안흥", "코드": "DT_0003" },
      "지역코드": "34" }
  ]
}
```

**포인트 수를 여기 적지 않습니다.** 셀 수 있는 것은 저장하지 않습니다(계약-04).
엔진이 `points/` 를 읽어 셉니다.

### `points/<묶음>.json`

```json
{
  "_설명": "충남 포인트. 옮기는 도구가 만듭니다 — 손으로 고치려면 overrides/ 에",
  "_기준일": "2026-09-26",
  "포인트": [
    { "id": "taean-f-001",
      "권역": "taean",
      "갈래": "낚시",
      "이름": { "ko": "안흥항 방파제", "zh": null },
      "좌표": { "위도": 36.673, "경도": 126.130 },
      "지형": "방파제",
      "대상": ["gamseongdom", "ureok"],
      "철": "연중",
      "등급": "A",
      "방법": "원투·찌낚시",
      "메모": "테트라 구간 출입 제한",
      "배로가나": false,
      "출입": "자유",
      "확인일": "2026-09-19" }
  ]
}
```

**옛 자료와 달라진 것**

| 옛것 | 새것 | 왜 |
|---|---|---|
| `name` | `이름.ko` / `이름.zh` | 중국어를 한 자료에 (계약-02) |
| `targets: ["감성돔"]` | `대상: ["gamseongdom"]` | 아이디로 이어 어종 쪽과 연결 |
| `lat` `lng` | `좌표.위도` `좌표.경도` | 뒤바뀌는 사고를 막으려고 이름을 붙임 |
| (없음) | `id` | 이름이 바뀌어도 안 깨지게 |
| (없음) | `출입` | 자유 · 확인필요 · 허가필요 · 금지 · 배로만 |
| (없음) | `확인일` | 언제 자료인지 밝힘 |

### 지우면 안 되는 것 표시 (계약-18)

```json
{ "_지우지_말_것": "주소 예약표 — 생성기가 씁니다",
  "_예약된_아이디": ["pohang-fest-02", "pohang-fest-03"] }
```

주석이 아니라 **자료 안에** 적습니다. 코드는 주석보다 강합니다.

## 다국어

한 자료에 두 언어를 함께 둡니다. 파일을 나누면 어긋납니다.

```json
"이름": { "ko": "태안", "zh": "泰安" }
"설명": { "ko": "...", "zh": null }
```

`zh` 가 `null` 이면 **중국어 쪽을 만들지 않습니다.** 번역 안 된 것을 억지로
중국어 쪽으로 내보내지 않습니다.

**검사**: 한국어가 있는데 중국어가 없으면 **알림**(막지는 않음 — 계약-21)

## 검사 (계약-25)

옮긴 뒤 **전수로** 봅니다. 3,603곳이라도 1초면 끝납니다.

| 무엇 | 어떻게 |
|---|---|
| 개수 | 옛것 = 새것 |
| 아이디 | 모두 있고, 겹치지 않음 |
| 좌표 | **위도 33~39 · 경도 124~132** (한반도) |
| | → 위도·경도를 뒤바꿔 넣으면 범위 밖이라 바로 잡힙니다 |
| 이름 | 빈 것 없음 |
| 대상 어종 | `species.json` 에 있는 아이디인가 |
| 권역 | `index.json` 에 있는 아이디인가 |
| 날짜 | `YYYY-MM-DD` |
| 전화 | `0\d{1,2}-\d{3,4}-\d{4}` |

## 자료를 더할 때

1. `data/schema/` 에 모양을 적습니다
2. `data/raw/` 에 파일을 만듭니다
3. **`refresh.json`(갱신 대장)에 한 줄 더합니다** — 안 적으면 검사가 잡습니다
4. 템플릿을 만듭니다

**엔진 코드는 안 고칩니다.** 자료를 읽어 무엇을 만들지 스스로 정합니다(계약-11).
