# 미리 받은 물때 — 어떻게 채워지고, 어떻게 되돌리나

2026-10-14 주인 지시로 만들었습니다.
「물때 딜레이 없어야해 이거 로딩느리면 방문자 바로 나가」
「수동은 잊어버릴 경우 위험성이 매우 커 **자동화로 가야 해**」
「60일로 진행하고 **이상이 발생할 경우에 대비해 장치를 만들어**」

---

## 0. 한눈에

손님이 보는 물때는 **미리 받아 둔 파일**에서 나옵니다.

```
손님  →  /assets/tide/{권역}.json  (8~16ms, 정부 API 를 안 거침)
         없거나 낡으면 → api/tide-cache.php (지금까지 쓰던 길)
```

그 파일은 **서버가 스스로** 채웁니다. 사람이 기억하지 않아도 됩니다.

```
손님이 옴 → tide.js 가 「남은 날 < 30일」이면 뒤에서 한 번 부탁
          → api/tide-refresh.php 가 권역 하나·열흘치를 채움
          → 검증 통과한 것만 교체 (임시파일 → 이름 바꾸기)
```

---

## 1. 채워지는 두 가지 길

### ㉠ 평상시 — **방문자 트리거** (자동)

`tide.js` 가 읽은 파일의 **남은 날이 30일 미만**이면, 뒤에서
`tide-refresh.php?t=공개암호` 를 **한 번** 부릅니다.
**응답을 기다리지 않으므로 손님은 아무것도 기다리지 않습니다.**

서버는 **7분에 한 걸음**, **권역 하나 · 열흘치**만 채웁니다.
`max_execution_time` 이 30초이고 정부 API 가 느릴 때는 하루치에
3~4초씩 걸리므로, **조금씩 여러 번**이 안전합니다.

★ 처음에는 20분이었는데 **7분으로 줄였습니다**(2026-10-14 감사
  지적). 20분이면 하루 72걸음뿐이라 오래 쉰 뒤 따라잡기가 너무
  느렸습니다. 7분이면 하루 205걸음이고, 한 걸음에 정부 호출
  10번이라 **2,050건** — 하루 한도 10,000건 안입니다.

★ 60일이 차 있으면 **한 달 동안 아무 일도 안 합니다.**

### ㉢ 손님이 없는 밤 — **깃허브가 깨웁니다** (자동)

주인 지시였습니다 — 「**매년 매월 매일 매시각 자동으로 나오도록,
중간에 내 개입이 없도록**」. 그런데 ㉠ 은 **손님이 와야** 돕니다.
새벽이나 비수기에 손님이 끊기면 아무도 부탁하지 않습니다.

그 빈틈을 `.github/workflows/tide-poke.yml` 이 메웁니다.
**한국 시간 02·06·10·14·18·22시**, 네 시간마다 주소를 **한 번**
두드립니다. 받아오고 검증하고 바꾸는 일은 전부 서버가 합니다.

- 비밀값이 **필요 없습니다** — 공개 암호를 씁니다
- 실패해도 **아무 일도 일어나지 않습니다**
- 한 번 약 1분 × 하루 6번 × 30일 = 월 **약 180분**
  (깃허브 무료 한도 2,000분의 **9%**)

★ 처음에는 7분씩 쉬며 **여덟 걸음**을 걷게 했습니다. 한 번 도는
  데 **50분**이라 하루 6번이면 월 **9,000분** — 한도를 **네 배
  넘깁니다.** 게다가 `timeout-minutes` 가 루프보다 짧아 매번
  중간에 취소될 참이었습니다. 둘 다 감사팀이 잡았습니다.
  그래서 **한 번 두드리고 끝냅니다.**

  걸음이 모자라지 않습니다 — 하루 6걸음 × 30일 = **180걸음**인데,
  한 달에 한 번 60일치를 새로 채우는 데 드는 것이 57권역 × 3구간
  = **171걸음**입니다. ㉠ 의 방문자 부탁이 함께 돌아 더 빨리 찹니다.

★ 끄려면 그 파일의 `schedule:` 두 줄을 주석 처리하거나 깃허브
  Actions 에서 **Disable** 합니다. 꺼도 ㉠ 은 그대로 돕니다.

### ㉡ 초기 채우기 — **관리 암호로 몰아서** (사람이 시작)

처음 60일을 채울 때는 방문자 트리거만으로는 느립니다.
그때는 **관리용 암호**로 권역마다 차례로 부릅니다.

```
api/tide-refresh.php?t=관리암호&only={권역}
```
· `only=` 는 **관리용 암호만** 쓸 수 있고 **간격을 건너뜁니다**
· 권역 사이에 쉬면서 순서대로 — 57권역 × 3구간 ≈ 2~3시간
· 정부 호출 1,700건 내외 (하루 한도 10,000건 안)

---

## 2. 암호가 둘인 까닭 ★ 중요

| | 어디에 | 할 수 있는 것 |
|---|---|---|
| **공개용** | `tide.js`·깃허브 일꾼 — **누구나 봅니다** | `only=` 불가 · **7분 간격 반드시** |
| **관리용** | 서버 안에만 | `only=` 가능 · 간격 면제 |

하나로 두면, 공개된 암호로 `only=` 를 되풀이해 **정부 하루 한도를
태울 수** 있습니다. 그러면 사이트의 **다른 물때 기능까지 막힙니다.**
그래서 나눴습니다.

### ★ 관리용 암호는 **어디에도 적지 않습니다** (2026-10-14 사고)

제가 `engine/fetch_tide.py` 에 관리용 암호를 **기본값으로** 박아
두었고, 그 파일이 **공개 저장소**에 올라갔습니다. 저장소가 비공개인
줄 알았는데 **확인하지 않았습니다.** 감사팀이 찾아 서버 암호를
바꿔 막았습니다.

- 쪽 코드·저장소·문서·주고받는 글 **어디에도 적지 않습니다**
- `fetch_tide.py` 는 환경변수 **`BADAGAJA_TIDE_ADMIN`** 으로만
  받습니다. **없으면 기본값을 쓰지 않고 오류로 끝냅니다** —
  조용히 안 되는 것보다 크게 멈추는 편이 낫습니다
- 공개용 암호(`bdg-refresh-pub-...`)는 **설계상 드러나도 됩니다**.
  `only=` 를 못 쓰고 간격을 반드시 지키기 때문입니다

## 3. 상태 보기

```bash
python -m engine.check_tide_live --서버    # 서버가 적어 둔 것 (한 번에)
python -m engine.check_tide_live           # 57개를 직접 받아 대조
python -m engine.check_tide_live --빠르게  # 대표 5곳만
```

`--서버` 는 `_status.json` 을 읽어 표와 **한 줄 요약**을 냅니다.

| 남은 날 | 뜻 |
|---|---|
| 14일 이상 | 넉넉합니다 |
| **14일 미만** | 갈아 줄 때입니다 |
| **7일 미만** | **폴백 임박** — 화면이 정부 API 로 되돌아갑니다 |

★ 폴백되어도 **손님 화면은 멀쩡합니다.** 느려질 뿐입니다.

---

## 4. 손으로 받는 길 (서버가 못 따라잡을 때만)

```bash
python -m engine.fetch_tide --날수 60     # 받습니다 (몇 시간)
python -m engine.check_tide_files         # ★ 통과해야 올립니다
python -m engine.build                    # site/assets/tide/ 로 옮김
# 감독실이 백업 → 업로드 → check_tide_live 로 확인
```

★ **서버 자가 갱신이 도는 동안에는 쓰지 마십시오.**
  같은 정부 API 를 동시에 두드려 서로 느려집니다.
★ `check_tide_files` 는 **날 수가 줄면 거부**합니다 — 서버가
  이미 늘려 둔 것을 덮어 되돌리는 것을 막습니다.

---

## 5. 되돌리는 법

### 서버가 바꾼 것을 되돌리려면

직전본이 **`assets/tide/_prev/{권역}.json`** 에 있습니다.
그것을 `assets/tide/{권역}.json` 로 덮으면 됩니다.

### 전부 되돌리려면

**`assets/tide/` 폴더를 통째로 지우십시오.**

★ 지우는 것이 안전한 까닭: 파일이 없으면 화면이 **지금까지 쓰던
  길**로 갑니다(`api/tide-cache.php`). 느려질 뿐 **고장나지
  않습니다.** 되돌릴 옛 파일이 없을 때도 마찬가지입니다.

### 자가 갱신을 멈추려면

**`api/tide-refresh.php` 를 지우십시오.** 그 파일이 없으면
`tide.js` 의 부탁이 404 를 받고 **조용히 넘어갑니다.**
손님에게는 아무 일도 일어나지 않습니다.

---

## 6. 이상이 나면 어디를 보나

| 증상 | 먼저 볼 것 |
|---|---|
| 물때가 안 나옴 | `check_tide_live --서버` — 404 인지 폴백인지 |
| **시각이 이상함** | **그 파일부터 지우십시오.** 지우면 정부 API 로 돌아가 맞는 값이 나옵니다. 원인은 그다음에 |
| 갑자기 느려짐 | 남은 날이 7일 미만이라 폴백 중인지 |
| 빈 날이 많음 | 자가 갱신이 채웁니다 — 조석은 불변이라 한 번만 성공하면 끝 |
| 자가 갱신이 안 돎 | `_status.json` 의 「마지막 걸음」 시각 · `_lock` 이 남았는지 |

## 7. 왜 이렇게 만들었나 (까닭 기록)

- 간조·만조는 **천문 계산값**이라 변하지 않습니다. 그래서 미리
  받아 둘 수 있습니다.
- 정부 API 는 건강할 때 **70ms** 인데 **간헐적으로 응답이
  없습니다** — 같은 주소가 1.97초였다 133초였다 합니다.
  손님이 그걸 그대로 맞아 **32초**를 기다린 적이 있습니다.
- 받을 때마다 **다른 날이 빕니다.** 그래서 「다 찬 것만 저장」이
  아니라 **합치기**로 모읍니다. 한 번만 성공하면 그 날은 끝입니다.
- 화면은 파일의 **날짜를 보고 오늘 이전을 잘라냅니다.** 순서로
  꺼내면 만든 날이 「오늘」이 되어 **지난 물때를 보여 줍니다.**
  이 결함은 2026-10-14 올리기 직전에 감사팀이 찾아냈습니다.
- `/data/` 는 서버가 막습니다(403 — 주인 규칙 11 을 지키는 장치).
  손님이 읽을 파일은 **`/assets/` 아래**에 둡니다.
- **절대 나빠지지 않게** 만들었습니다 — 새 자료가 검증을 통과해야만
  바꾸고, 날 수가 줄면 거부하고, 받다 실패하면 옛 파일 그대로입니다.
