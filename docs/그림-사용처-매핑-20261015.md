## 3. 최소 해상도 — **쓰임에 따라 다릅니다**

한 줄로 자르지 않았습니다. 자리마다 요구가 다르기 때문입니다.

| 쓰임 | 기준 | 지금 |
|---|---|---|
| **공유 미리보기(og:image)** | 150×150 **초과** · 가로세로 **3:1 이내** (네이버·구글 가이드, 주인 규칙 28) | **451쪽 모두 통과** |
| 권역 대표 사진(히어로) | 가로 940 이상이면 PC 1440 에서 또렷 | coast 가장 작은 것 **500×375** — 작은 축 |
| 쪽 안 작은 그림 | 보이는 크기의 2배면 충분 | `ui/step` 268×87 — 아이콘이라 괜찮음 |

★ **가장 작은 `coast` 500×375 한 장**만 눈여겨볼 값입니다.
  어느 쪽에 쓰이는지, 히어로인지 작은 카드인지에 따라 다릅니다 —
  **지시 주시면 그 한 장을 찾아 보고하겠습니다.**

## 4. 자동 보정 — **됩니다. 다만 권하지 않는 것이 있습니다**

| 무엇 | 자동으로 | 권하나 |
|---|---|---|
| 크기 줄이기 | 됩니다 (Pillow 있음) | **예** — 1920 짜리를 쓰는 자리가 1440 이면 낭비 |
| 다시 압축 | 됩니다 | **예** — 품질 85 로 보통 30~50% 줄어듭니다 |
| webp 로 바꾸기 | 됩니다 | **조건부** — 더 작아지지만 쪽의 `<img>` 를 함께 고쳐야 |
| 잘라내기(크롭) | 됩니다 | **아니오** ★ |
| 밝기·대비 손대기 | 됩니다 | **아니오** ★ |

★ **잘라내기와 색 보정은 자동으로 하지 않는 것이 맞습니다.**
  바다 사진은 **수평선 위치와 하늘 비율**이 인상을 정합니다.
  기계가 가운데로 자르면 수평선이 어긋나고, 노을 사진의 색을
  「보정」하면 그 사진을 고른 까닭이 사라집니다.
  주인 규칙 3 — 「바다가 주제로 보이는 사진」 — 을 기계가
  지킬 수 없습니다.

★ 크기·압축도 **원본을 덮지 않습니다.** 줄인 것을 따로 두고
  쪽이 그것을 가리키게 합니다. 되돌릴 수 있어야 합니다.

★ 촬영자 표기(주인 규칙 5·6)는 **자료에 있고 그림에 없습니다.**
  그림을 바꿔도 표기는 그대로 갑니다 — 안전합니다.

## 5. og:image 겹침 — **297쪽**

```
  og:image 가 있는 쪽 451장 · 서로 다른 그림 226가지
  겹치는 그림 72가지 → 그 때문에 겹친 쪽 297장
  가장 많이 겹치는 것: hero.jpg (10쪽·10쪽·9쪽·9쪽·9쪽 …)
```

주인 규칙 28 — 「og:image 는 **쪽마다 다른 사진**이어야 합니다」.

까닭은 **같은 권역의 낚시·해루질·축제 쪽이 같은 대표 사진**을
쓰기 때문입니다. 고치려면 사진을 더 구하거나, 권역 안에서
갈래마다 다른 사진을 고르게 해야 합니다.

★ **`jeju/spot` 29장이 여기에 쓰일 수 있습니다** — 제주 쪽
  겹침을 줄이는 데 바로 보탬이 됩니다.

범위가 커서 **지시 없이는 손대지 않습니다.**

## 6. 「26종」이 무엇인지 — **못 가렸습니다**

감독실이 말씀하신 「26종 이미지」와 **정확히 맞는 묶음이
없습니다.**

```
  가까운 것   jeju/spot 29장 · rig 32장 · species 35장
  정확히 26   없음
```

짐작해서 보고하면 틀립니다. **어느 것인지 알려 주시면** 그
묶음만 따로 자세히 내겠습니다. `python -m engine.map_images
--갈래 <이름> --자세히` 로 한 장씩 뽑을 수 있습니다.

---

## 7. 쓰는 법

```bash
python -m engine.map_images                      # 요약
python -m engine.map_images --자세히              # 갈래마다 낱낱이
python -m engine.map_images --갈래 jeju/spot --자세히
```

끝난값 — 쪽이 부르는데 없는 그림이 있으면 1, 없으면 0.
