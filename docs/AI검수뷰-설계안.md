# AI 검수 전용 읽기 뷰 설계안 (`/stats-review/`)

총감독 확정 2026-10-10 · 작업대장 #9 [P0]
**로컬·모의자료로만 만듭니다. 운영 배포·.htaccess·api 변경은 승인 전 금지.**

---

## 0. 왜 만드나

최종결정자만 보는 잠금 화면이면 총감독(ChatGPT)도 감독실(Claude)도
통계를 **눈으로 검수할 수 없습니다.** 지금 제가 「통계 화면을
고쳤습니다」 하고 올려도 숫자가 든 진짜 화면은 아무도 못 봅니다.

그래서 **집계값만 담은 읽기 전용 화면**을 따로 둡니다.
사람(최종결정자)이 쓰는 `/stats.html` 은 그대로 둡니다.

---

## 1. 접근 설계 — **후보 B 를 고릅니다**

| | 후보 A — 읽기전용 권한 + 서버 보관 비밀값 | **후보 B — 완전 비식별 집계 스냅샷** |
|---|---|---|
| 비밀값 | 하나 더 생김 (유효기간·회전·철회·감사 필요) | **없음** |
| 총감독 도구 호환 | 쿠키·헤더를 못 싣는 경우가 많아 **안 열릴 수 있음** | 평범한 주소라 **열림** |
| 샐 때 피해 | 권한이 새면 그 뒤로 계속 열림 | 집계값만이라 피해가 작음 |
| 만드는 품 | 서버 코드·회전·감사 로그 필요 (api/ 변경 = 승인 대상) | **서버 코드 없이 됨** |
| 막는 것 | 서버 권한 검사 | 내보낼 때 **아예 안 담음** |

**고른 까닭**

1. 총감독이 「ChatGPT 일반 웹 조회 도구는 로그인 쿠키·비밀 헤더를
   못 주입하는 경우가 많다」고 짚었습니다. 후보 A 는 **열리지 않을
   가능성이 큽니다.** 열리지 않는 화면은 검수에 쓸모가 없습니다.
2. 후보 A 는 비밀값을 하나 더 만듭니다. 비밀값은 **없는 것이 가장
   안전합니다.** 팀은 비밀값을 받지 않는다는 규칙과도 맞습니다.
3. 후보 A 는 `api/` 를 고쳐야 하고 그것은 승인 대상입니다.
   후보 B 는 **만드는 쪽에서 안 담으면** 끝납니다.

**다만 noindex 는 접근통제가 아닙니다.** 총감독 말씀 그대로
받아들여, 「누가 주소를 알면 볼 수 있다」를 전제로 **담는 것 자체를
집계값으로 한정**합니다. 주소를 비밀로 믿지 않습니다.

---

## 2. 위협 모델 — 무엇을 막나

| 걱정 | 어떻게 막나 |
|---|---|
| 방문자 개인이 드러남 | IP·원시 UA·검색어·연락처·쿠키·세션 아이디를 **아예 안 담음** |
| 비밀값이 샘 | 열쇠말·토큰을 쓰지 않음. 주소·HTML·JS·커밋 어디에도 없음 |
| 검수 화면에서 자료를 고침 | 서버로 가는 쓰기 길이 **없음**. 정적 파일 하나 |
| 검색에 뜸 | `noindex` + `robots.txt` + 사이트맵 제외 (보조 장치) |
| 주소가 새어 아무나 봄 | 집계값뿐이라 피해가 작음. 그래도 주소를 공개 링크로 걸지 않음 |
| 숫자를 보고 운영을 흉내 냄 | 수익·광고·구매는 **담지 않음** |

---

## 3. 담는 것 / 안 담는 것

### 담는 것 (집계값만)

* 날짜별 **방문 수 · 조회 수** (정의를 화면에 적음)
* 기간별 합계 — 오늘 · 7일 · 30일 · 이번 달
* 유입 갈래 비율 — 검색 · 직접 · 그 밖 · **확인 불가**
* 인기 쪽 상위 열 — **주소만**, 쿼리 문자열은 잘라냄
* 갱신 시각 (KST)
* **누락 기간** — 자료가 없는 날을 숨기지 않고 밝힘
* 수집 원천 · 로봇 거르기 상태 — **서버가 알려 줄 때만**.
  모르면 「확인되지 않음」이라 적고 ✓ 를 쓰지 않음

### 안 담는 것

IP · 원시 UA · 검색어 · 연락처 · 토큰 · 쿠키 · 열쇠 값 ·
원본 로그 · 개별 방문자 줄 · 수익 · 광고 수 · 구매

### 「없음」과 「0」을 가릅니다

| 화면 표시 | 뜻 |
|---|---|
| `1,284` | 그만큼 셌습니다 |
| `0` | **세었고 0 이었습니다** |
| `—` | 측정하지 않는 항목입니다 |
| `못 받음` | 측정은 하는데 이번에 못 받았습니다 |

이 넷을 섞으면 숫자가 거짓이 됩니다.

## 4. 권한 가르기

| | `/stats.html` (운영자) | `/stats-review/` (AI 검수) |
|---|---|---|
| 누가 | 최종결정자 | 총감독 · 감독실 |
| 인증 | 열쇠말 | 없음 (집계값뿐) |
| 자료 | 서버에서 실시간 | **만들 때 박힌 스냅샷** |
| 개인정보 | 지금도 안 보임 | 아예 안 담김 |
| 고치기·지우기 | 없음 | 없음 (쓰기 길 자체가 없음) |
| 검색 노출 | 사이트맵 제외 + Disallow | 같음 + `noindex` |
| 갱신 | 열 때마다 | 사람이 만들 때 (시각을 적음) |

## 5. 스냅샷을 어떻게 만드나

**서버 코드를 고치지 않습니다.**

1. 최종결정자가 `/stats.html` 에서 열쇠말을 넣고 봅니다 (지금과 같음)
2. 그 화면에 **「검수용 집계 내려받기」** 단추를 하나 둡니다
3. 누르면 **브라우저 안에서** 이미 받은 자료에서 집계값만 추려
   `stats-review.json` 파일로 저장합니다 — 서버로 아무것도
   보내지 않고, 개인정보 항목은 추릴 때 빠집니다
4. 그 파일을 실행팀이 받아 `data/raw/` 에 넣고 다시 만들면
   `/stats-review/index.html` 이 그 숫자로 그려집니다

이 길의 좋은 점
* `api/` 를 안 고칩니다 (승인 대상이 아님)
* 열쇠말이 **브라우저 밖으로 안 나갑니다**
* 무엇이 담겼는지 파일을 열어 보면 그대로 보입니다
* 자료가 없으면 쪽이 안 만들어집니다 — 가짜 숫자가 안 생깁니다

**TTL·회수**: 스냅샷에 만든 시각을 박고, 화면 맨 위에
「○○월 ○○일 ○○시 기준 · ○일 지남」을 띄웁니다. 7일이 지나면
**빨갛게** 「오래된 스냅샷입니다」라고 알립니다. 회수는 파일을
지우고 다시 만들면 됩니다.

## 7. 시험할 것

| 무엇 | 어떻게 | 바라는 것 |
|---|---|---|
| 권한 없는 고치기·지우기 | 쪽에 form·fetch 쓰기가 있는지 | **0개** |
| 비밀값 노출 | 쪽·JS·JSON 전문에서 열쇠말·토큰 찾기 | **0건** |
| 개인정보 | JSON 에서 IP 꼴·UA 꼴·연락처 꼴 찾기 | **0건** |
| noindex | 메타와 robots.txt | 둘 다 있음 |
| 사이트맵 | sitemap.xml 에 없는지 | 없음 |
| 집계값 맞음 | 스냅샷 합계 = 날짜별 합 | 같음 |
| 「없음」과 「0」 | 모의자료로 넷을 다 만들어 봄 | 넷이 달라 보임 |
| 모바일 | 360·390·430px 넘침 | 0 |

모두 검사기로 만들어 판정에 물립니다 — `engine/check_review_view.py`.

## 8. 아직 못 정한 것 (총감독께 여쭙니다)

1. **비배포 시범을 어떻게 하나.** 제 생각은 로컬에 모의자료로
   띄워 **화면을 캡처해 올리는 것**입니다. 그러면 주소도 비밀값도
   나가지 않습니다. 「이 모양이면 읽히는가」를 먼저 보고, 괜찮으면
   그때 배포 승인을 여쭙겠습니다.
2. **주소를 무엇으로 할까요.** `/stats-review/` 는 짐작하기 쉽습니다.
   집계값뿐이라 큰 문제는 아니지만, 더 긴 이름을 쓸지 정해 주십시오.
3. **스냅샷을 누가 언제 만드나.** 최종결정자가 누를 단추이므로
   그분의 손이 필요합니다. 주마다 한 번이면 될지, 검수 때마다일지.
