# 동호회 개설 문의 — 내부 접수 구현 설계

총감독 지휘 2026-10-13 ⓑ — 「로컬 설계·구현·시험까지. **운영 반영·개인정보 수집 활성화는 별도 승인 전 금지.** mailto 사용 금지」

**서버에 아무것도 만들지 않았습니다.** 로컬 설계와 시험만입니다.

---

## 0. 지금 상태 (실측)

| 주소 | 응답 | 뜻 |
|---|---|---|
| `/data-private/` | **404** | 폴더가 **없습니다** (막힌 것이 아님) |
| `/data-private/club/` | 404 | 없음 |
| `/api/club-apply.php` | 404 | 없음 |
| `/api/hit.php` | 200 | 서버에만 있는 기존 코드 |

★ **404 는 「막혔다」가 아니라 「없다」입니다.**
만드는 순간 열릴 수 있습니다. 그래서 **차례**가 중요합니다.

---

## 1. 반드시 지킬 차례 — 먼저 막고 나중에 만듭니다

```
  ①  .htaccess 에 Deny 를 **먼저** 올립니다
  ②  빈 시험 파일을 올려 바깥에서 **403 인지 눈으로** 봅니다
  ③  그 확인이 끝난 **뒤에야** api/club-apply.php 를 올립니다
  ④  접수를 켭니다 (data/raw/site.json 의 `받는곳` 한 줄)
```

이 차례를 거꾸로 하면 **첫 접수부터 공개**됩니다.

★ `.htaccess` 주의 (주인 규칙 27)
- **BOM 을 붙이면 무조건 500** 입니다. `encoding='utf-8'`(BOM 없이)
- 한 번에 **한 가지만** 고치고, 올린 직후 `curl` 로 응답 코드 확인
- 500 이 나면 **먼저 되돌려 사이트를 살리고** 원인을 찾습니다

---

## 2. 무엇을 만드나

```
  /club/support.html        폼 (생성기가 만듭니다 — 이미 있음)
         │ POST
         ▼
  api/club-apply.php        ← 새로. 약 90줄
         ├ ① 보낸 곳이 우리 쪽인지 봅니다 (CSRF)
         ├ ② 담을 칸만 골라 담습니다 (화이트리스트)
         ├ ③ 길이를 자릅니다
         ├ ④ 1분에 한 번만 받습니다
         └ ⑤ 파일 잠금 뒤 한 줄 덧붙입니다
                  ▼
  data-private/club/2026-10.jsonl   ← 웹에서 못 읽는 자리
```

---

## 3. 담을 것 — **담을 것만 적습니다**

```
  받은때 · 동호회이름 · 지역 · 사람수 · 하는것
  연락 (손님이 적은 것 하나)
  하고싶은말
```

**안 담는 것** (받아도 버립니다)
- IP 주소 · User-Agent · 쿠키 · 세션 · 리퍼러
- 폼에 없던 칸 (누가 끼워 넣어도 버립니다)

★ 「이건 빼자」가 아니라 **「이것만 담자」**로 짭니다.
폼에 칸이 늘어도 새 자료가 저절로 새지 않습니다.

---

## 4. 막는 장치

| 무엇 | 어떻게 |
|---|---|
| **CSRF** | 폼을 낼 때 한 번 쓰는 표를 심고, 받을 때 맞춰 봅니다. 표가 없거나 다르면 버립니다 |
| 다른 곳에서 보내기 | `Origin`·`Referer` 가 `badagaja.com` 인지 봅니다 |
| 로봇이 쏟아붓기 | 같은 접속에서 **1분에 한 번**만 |
| 너무 긴 글 | 이름 40자 · 지역 40자 · 연락 80자 · 하고싶은말 1,000자 |
| 파일이 끝없이 커짐 | 한 달 파일이 **1MB** 넘으면 안 받고 알립니다 |
| 동시에 보내기 | `flock` 으로 잠그고 덧붙입니다 (`hit.php` 와 같은 방식) |
| 이상한 값 | 담을 칸만 골라 담습니다 (3절) |

---

## 5. 동의 문구 — 폼 바로 위에 둡니다

> **적어 주시는 것**
> 동호회 이름 · 지역 · 사람 수 · 하는 것 · 연락처 하나 · 하고 싶은 말
>
> **쓰는 곳** 문의에 답하는 데만 씁니다. 다른 데 쓰지 않습니다.
> **두는 기간** 6개월. 그 뒤 지웁니다.
> **보는 사람** 운영책임자만 봅니다.
> **안 받는 것** 주민등록번호·계좌·주소는 받지 않습니다. 적지 마세요.
>
> 보내기를 누르면 위 내용에 동의하신 것으로 봅니다.

★ 체크상자를 따로 두지 않습니다 — 보낼 것이 **이것뿐**이고
글이 짧아, 체크를 하나 더 두면 오히려 안 읽고 누릅니다.
다만 **「안 받는 것」을 굵게** 적어 민감한 값을 애초에 막습니다.

---

## 6. 되돌리기

| 무엇 | 어떻게 |
|---|---|
| 끄는 법 | `data/raw/site.json` 의 `받는곳` 을 **빈 문자열로** |
| 그러면 | 생성기가 폼을 안 만들고 「준비 중」 안내로 돌아갑니다 |
| 품 | **자료 한 줄.** 쪽을 손대지 않습니다 |
| 서버 파일 | `api/club-apply.php` 를 지우면 끝. 다른 것에 안 엮입니다 |
| 받아 둔 자료 | 그대로 남습니다. 지우려면 파일을 지웁니다 |

---

## 7. 로컬에서 시험하는 법

서버에 올리지 않고 **내 컴퓨터에서** 돌려 봅니다.

```bash
# 1. 로컬 PHP 서버 (api/ 와 data-private/ 를 임시로 만들어)
php -S 127.0.0.1:8080 -t .

# 2. 보내 보기 — 정상
curl -X POST http://127.0.0.1:8080/api/club-apply.php \
     -d "club_name=시험동호회&region=여수&contact=test@example.com" \
     -H "Origin: http://127.0.0.1:8080"

# 3. 막히는지 보기 — CSRF 표 없이
curl -X POST http://127.0.0.1:8080/api/club-apply.php -d "club_name=x"

# 4. 담기지 말아야 할 것이 안 담겼는지
cat data-private/club/*.jsonl
```

**시험이 끝나면 로컬 `data-private/` 를 지웁니다.** 시험값이라도
개인정보 꼴이면 남기지 않습니다.

## 8. 승인받아야 움직이는 것

| # | 무엇 | 왜 |
|---|---|---|
| 1 | `.htaccess` 에 Deny 올리기 | 서버 설정 — 500 위험 (규칙 27) |
| 2 | `api/club-apply.php` 올리기 | 서버 코드 |
| 3 | `data-private/` 만들기 | **개인정보 저장소** |
| 4 | `받는곳` 채워 접수 켜기 | **수집 시작** |

**지금은 1~4 중 아무것도 안 했습니다.**
로컬 설계까지이고, 구현·시험은 승인 뒤에 하겠습니다 —
로컬이라도 `api/`·`data-private/` 를 만들면 **실수로 올라갈 위험**이
있어, 차례(①막기 → ②확인 → ③만들기)를 먼저 밟는 편이 안전합니다.
