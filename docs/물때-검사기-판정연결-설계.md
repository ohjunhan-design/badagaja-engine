# 물때 검사기를 판정에 어떻게 물릴까 — 설계안

2026-10-14 · 감독실 요구로 **먼저 보여 드리는 설계**입니다.
승인 전에는 붙이지 않습니다.

---

## 왜 설계를 먼저 보여 드리나

`check_architecture` 가 **「판정에 안 물린 검사기」를 막습니다.**
지금 세 개가 걸려 있습니다 —
`check_tide_files.py` · `check_tide_live.py` · `check_tide_integrity.py`.

그런데 **그냥 붙이면 안 됩니다.** 물때 검사기는 성질이 다릅니다.

| | 무엇을 보나 | 네트워크 | 결과가 흔들리나 |
|---|---|---|---|
| `check_tide_files` | 올릴 **파일** | 없음 | 아니오 |
| `check_tide_integrity` | **운영 서버** 57곳 | **씁니다** | 서버가 자라며 바뀝니다 |
| `check_tide_live` | 운영 **상태** | **씁니다** | 늘 바뀝니다 |

판정은 **같은 자료면 같은 결과**여야 합니다(계약·멱등성).
서버를 보는 검사기를 배포 판정에 넣으면, 서버가 자라는 동안
**같은 커밋이 통과했다 막혔다** 합니다. 그러면 판정을 믿을 수
없게 됩니다.

---

## 제안 — **자리를 셋으로 나눕니다**

### ㉠ 배포 판정 (`gate.py` 덧검사) — `check_tide_files` 만

```
('미리받은물때', 'check_tide_files.py', [], 300,
 '올릴 물때가 망가졌는가 (막음) · 모자람은 알림')
```

- **네트워크를 쓰지 않습니다.** 저장소의 파일만 봅니다.
- 같은 커밋이면 **언제나 같은 결과**입니다.
- 막는 것은 **망가짐**뿐입니다 —
  파일 없음 · 글 깨짐 · 오늘 없음 · 값 형식 오류 ·
  날 수 줄어듦 · 겹치는 날 값 변경
- 모자람(60일 미달 · 빈 날)은 **알림**입니다. 서버가 채우는
  중에도 배포를 막지 않습니다.

★ 다만 「날 수 줄어듦」은 **견줄 곳이 있을 때만** 봅니다
  (`--견줄곳`). 그 비교는 네트워크가 아니라 **직전 배포본**과
  하므로 흔들리지 않습니다.

### ㉡ 배포 **직전 차례** — `merge_live_tide` → 다시 `check_tide_files`

판정과 따로, 올리기 직전에 돕니다.

```
python -m engine.merge_live_tide        # 서버 것과 합칩니다
python -m engine.check_tide_files       # 통과해야 올립니다
```

재어 보인 것: 합치기 전 **막음 32가지** → 합친 뒤 **0가지**.
막고 끝내지 않고 **고치는 길**을 둡니다.

### ㉢ 깨우기 일꾼 (`tide-poke.yml`) — 서버를 보는 둘

정기 실행이 끝날 때 **운영 상태**를 찍습니다. 거기가 제자리입니다
— 이미 네 시간마다 서버를 두드리는 일꾼이니까요.

```yaml
- name: 지금 상태
  run: |
    python -m engine.check_tide_live --서버
    python -m engine.check_tide_integrity || true
```

- 날것 `curl` 대신 **한 줄 요약**이 로그에 남습니다
- `|| true` — 서버 상태가 나쁘다고 **일꾼을 실패로 만들지
  않습니다.** 알리는 것이 일입니다
- **암호·열쇠는 찍지 않습니다.** 공개 로그입니다
- 파이썬이 필요하니 `actions/checkout` + `setup-python` 을
  더해야 합니다. 한 걸음이 1분 → 2~3분이 됩니다.
  공개 저장소라 Actions 는 무료 무제한이므로 괜찮습니다

## 이렇게 하면 무엇이 좋아지나

| | 지금 | 설계 뒤 |
|---|---|---|
| 판정이 흔들리나 | — | 안 흔들립니다 (네트워크 안 씀) |
| 서버 상태를 누가 보나 | 사람이 생각나면 | 네 시간마다 일꾼이 |
| 망가진 물때가 올라가나 | 막습니다 | 막습니다 (그대로) |
| 모자란 물때가 배포를 막나 | **막습니다** | 안 막습니다 |
| 안 물린 검사기 | **3개** | 0개 |

## 묻습니다

1. ㉠ 을 `gate.py` 덧검사에 붙여도 되겠습니까
2. ㉡ 을 어디에 적을까요 — `release.py` 차례에 넣을지,
   문서의 손 작업으로 둘지 (감독실이 올리므로 감독실 차례가
   맞을 것 같습니다)
3. ㉢ 때문에 `tide-poke.yml` 이 2~3분으로 늘어나는 것이
   괜찮겠습니까. 싫으시면 **상태만 `curl` 로 두고**
   `check_tide_integrity` 는 주간 일꾼으로 돌리는 길도 있습니다

★ 승인 전에는 붙이지 않습니다. 그동안 `check_architecture` 는
  「안 물린 검사기 3개」로 막는데, 그것이 **올바른 동작**입니다.
