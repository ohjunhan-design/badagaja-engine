# 검수 뷰 스냅샷 — 안전한 배치 방식 제안

총감독 결정 2026-10-10 · 작업대장 #9
「스냅샷은 수동 주1회 대신 **인증된 집계에 접근 가능한 안전한
배치 방식 제안 우선**(구현·배포 전 권한·데이터 보호 검수)」

**이 문서는 제안입니다. 구현하지 않았고 배포하지 않았습니다.**

---

## 0. 왜 수동이 모자라나

앞선 설계는 최종결정자가 단추를 눌러 파일을 내려받는 방식이었습니다.
그 길의 흠 셋.

1. **사람 손이 필요합니다.** 바쁘면 스냅샷이 늙고, 늙은 숫자로
   검수하면 틀린 판단을 합니다.
2. **빠뜨리면 모릅니다.** 안 눌렀는지 서버가 죽었는지 구별이 안 됩니다.
3. **늘 같은 사람이 눌러야 합니다.** 그분이 없으면 멈춥니다.

---

## 1. 세 가지 길과 견줌

| | A. 서버 배치(cron + PHP) | B. 깃허브 액션 배치 | C. 수동 (앞선 안) |
|---|---|---|---|
| 사람 손 | 없음 | 없음 | **필요** |
| 비밀값을 어디 두나 | **서버 안**(config.php, 이미 있음) | 깃허브 Secrets | 브라우저 안 |
| 비밀값이 새나 | 서버 밖으로 안 나감 | 깃허브로 **나감** | 안 나감 |
| api/ 를 고치나 | **고침** (승인 필요) | 안 고침 | 안 고침 |
| 만드는 품 | 중 | 소 | 소 |
| 끊기면 아나 | 갱신 시각으로 앎 | 액션 기록으로 앎 | 모름 |
| 유료 호출 | 없음 | 없음(무료 분) | 없음 |

---

## 2. **A 를 권합니다** — 서버 안에서 끝내기

### 왜

* 비밀값(`config.php` 의 열쇠말)이 **서버 밖으로 한 번도 안 나갑니다.**
  B 는 같은 값을 깃허브 Secrets 에 또 두어야 하고, 비밀값이
  **두 곳에 있으면 두 배로 샙니다.**
* 팀은 비밀값을 받지 않는다는 규칙을 그대로 지킵니다. 제가
  값을 보지 않고도 서버가 알아서 합니다.
* 이미 `api/stats.php` 가 그 값으로 집계를 읽습니다. 같은 자리에서
  한 번 더 쓰는 것뿐입니다.

### 어떻게

```
서버 cron (하루 한 번, 새벽 4시 KST)
  └ api/snapshot.php 를 부릅니다 (서버 안에서만 부를 수 있게)
      ├ config.php 의 열쇠말로 집계를 읽습니다 (이미 있는 길)
      ├ **집계값만** 추려 냅니다 (아래 ③ 목록)
      ├ /stats-review/data.json 으로 씁니다
      └ 만든 시각을 함께 박습니다
```

쪽(`/stats-review/index.html`)은 그 json 을 읽어 그립니다.
지금은 만들 때 숫자를 박아 넣는데, 그 부분만 바꾸면 됩니다.

### 지켜야 할 것

| 무엇 | 어떻게 |
|---|---|
| 밖에서 `snapshot.php` 를 못 부르게 | `php_sapi_name() === 'cli'` 이거나 `127.0.0.1` 에서만. 아니면 403 |
| 비밀값이 결과에 안 섞이게 | 추릴 때 **담을 것만 골라 담습니다**(화이트리스트). 통째로 복사하지 않습니다 |
| 개인정보가 안 섞이게 | `engine/build_review.py` 의 `몸수색()` 과 같은 검사를 **쓰기 전에** 돌립니다. 걸리면 안 씁니다 |
| 쓰다 말면 | 임시 파일에 쓰고 **다 되면 바꿔치기**(원자적 교체). 반쯤 쓰인 파일이 안 보입니다 |
| 끊기면 알게 | 쪽에 「○일 지남」을 띄웁니다. 2일이 넘으면 빨갛게 |
| 되돌리기 | `data.json` 을 지우면 쪽이 「스냅샷이 없습니다」를 보입니다 |

### 바꿔야 하는 것

* `api/snapshot.php` **새 파일 하나** (약 60줄로 봅니다)
* 서버 cron 한 줄
* `engine/build_review.py` — 숫자를 박는 대신 json 을 읽게

**세 가지 모두 총감독 승인 전에는 하지 않습니다.**
특히 `api/` 는 승인 대상이고, cron 은 서버 설정입니다.

## 3. 담을 것 (화이트리스트)

**담을 것만 적습니다.** 「이건 빼자」가 아니라 「이것만 담자」로
짜야 새 자료가 생겨도 안 샙니다.

```
만든때 · 시간대 · 달 · 받은달
날짜별[날짜] = { 방문, 조회 }          ← 이 둘만
유입 = { 검색, 직접, 그밖, 확인불가 }   ← 수만
인기쪽[] = { 주소, 조회 }              ← 쿼리 잘라낸 주소
기기 = { 휴대폰, 컴퓨터 }
수집 = { 원천, 로봇거르기 }
못받음[] · 측정안함[]
```

이 목록에 없는 열쇠는 **무엇이든 안 담깁니다.**

## 4. 주기

| 안 | 좋은 점 | 나쁜 점 |
|---|---|---|
| 하루 한 번 (**권함**) | 늘 하루 안쪽 자료 · 서버 부담 작음 | — |
| 한 시간마다 | 거의 실시간 | 서버를 자주 깨움. 검수에는 과함 |
| 주 한 번 | 가벼움 | **늙은 숫자로 검수하게 됨** |

검수는 「어제까지 어땠나」를 보는 일이라 **하루 한 번이면 넉넉**합니다.
새벽 4시로 두면 그날 치가 아직 안 찬 혼동도 없습니다.

---

## 5. B(깃허브 액션)를 안 고른 까닭

품은 가장 적습니다. 그러나 **비밀값을 깃허브에 또 둬야** 합니다.
지금 열쇠말은 서버 `config.php` 한 곳에만 있습니다. 두 곳이 되면

* 어느 쪽을 바꿔야 하는지 헷갈립니다
* 한 쪽만 바꾸면 조용히 어긋납니다
* 새는 길이 둘이 됩니다

비밀값은 **있는 곳이 적을수록 안전합니다.** 품을 아끼자고 늘리지
않는 것이 맞다고 봅니다.

---

## 6. 승인받고 싶은 것

1. **A(서버 배치)로 가도 될지.** 아니면 B 나 수동을 고르실지.
2. 간다면 `api/snapshot.php` 를 **먼저 글로 써서** 보여 드릴지,
   코드까지 써서 보여 드릴지. (어느 쪽이든 서버에는 안 올립니다)
3. 주기를 하루 한 번으로 둘지.

**승인 전까지는 지금 방식(모의 자료로 만든 쪽)을 그대로 둡니다.**
