# 쪽 갈래 계약 — `public` / `internal-admin` / `internal-review`

총감독 확정 2026-10-10 · 작업대장 #9 · 순서 2번

**이 문서는 설계안입니다. 아직 한 줄도 구현하지 않았습니다.**

---

## 0. 왜 필요한가 — 실제로 터진 일

판정 #161 뒤 로컬 뮤테이션 시험이 **8가지 실패**를 냈습니다.
까닭을 쫓으니 **뿌리가 하나**였습니다.

제가 만든 `/stats-review/index.html` 한 쪽을, 검사기 일곱이
**손님용 공개 쪽으로 보고** 잡습니다.

| 검사기 | 무엇을 요구하나 | 검수 뷰의 실제 |
|---|---|---|
| `check_seo` | 설명 · og 다섯 · 트위터 카드 | **일부러 없음** (공유 안 함) |
| `check_canonical` | 대표 주소 | **일부러 없음** (색인 대상 아님) |
| `check_photos` | 보이는 것 · og:image | 막대가 **CSS div** 라 안 세어짐 ※ |
| `check_assets` | 아이콘 선언 | 없음 |
| `check_reachable` | 들어갈 길 | **일부러 없음** (주소만 알면 열림) |
| `check_design` | 옛 쪽이 가졌던 것 | 옛 쪽에 없던 쪽 |
| `check_golden`·`check_canary` | 기준선·표본 그대로 | 새로 생김 (합 4 → 7) |

대부분은 쪽을 고칠 문제가 아닙니다. **쪽마다 지켜야 할 것이
다른데, 검사기가 그것을 모르기 때문**입니다.

### ※ 하나는 제가 틀렸습니다 — `check_photos`

처음에 「`check_photos` 가 **사진만** 세니 고쳐야 한다」고
적었습니다. **확인해 보니 틀렸습니다.** 그 검사기는 이미
`<svg>` 를 보이는 것으로 셉니다(2026-09-26 에 축제 막대 때문에
이미 고쳐 둔 것입니다).

| 쪽 | `<img>` | `<svg>` | 판정 |
|---|---|---|---|
| `site/stats.html` | 0 | 8 | **통과** |
| `site/festival/index.html` | 2 | 8 | 통과 |
| `site/stats-review/index.html` | **0** | **0** | 어김 |

검수 뷰가 걸린 까닭은 막대를 **CSS `div`**(`rv-bar` 28개)로
그렸기 때문입니다. **검사기가 맞고, 고칠 곳은 제 쪽입니다.**

### ※※ 그 뒤 — 「svg 로 바꾸자」도 성급했습니다

처음에는 「검수 뷰 막대를 `<svg>` 로 바꾸면 끝」이라 적었습니다.
**그것도 거뒀습니다.** 두 가지 때문입니다.

1. **총감독이 통과시킨 디자인 시안을 깨뜨립니다.** CSS 막대로
   그린 날마다·주마다 화면이 1차 시안으로 통과했습니다.
2. **검사를 통과하려고 `<svg>` 를 끼워 넣는 것은 속이는 짓입니다.**
   손으로 보니 검수 뷰에는 **눈으로 읽히는 것이 넉넉합니다** —
   날마다 막대 30칸 · 0인 날 빗금 · 주마다 막대 · 비율 막대 28줄.
   사람 눈으로는 **보입니다.** 못 보는 것은 검사기입니다.

즉 이것은 **거짓 양성**입니다. 「보이는 것」을 `<img>`/`<svg>` 로만
정의한 것이 좁습니다.

### 그래서 — 총감독께 올리는 넷째 물음

| 갈래 | 어떻게 | 흠 |
|---|---|---|
| ㉮ 자료를 심은 자리를 셉니다 | `style="width:NN%"`·`height:NNpx` 가 **여럿**(8개 이상)이면 그림으로 셉니다. 자료에서 계산한 값을 심은 자리라 장식 하나로는 안 됩니다 | 아주 못 속이는 것은 아닙니다 |
| ㉯ 쪽이 밝힙니다 | `<div class="rv-days" data-보이는것="날마다 방문 막대 30칸">` — 값이 비면 어김 | 거짓으로 적으면 사람이 봐야 압니다 |
| ㉰ 크롬으로 잽니다 | 칸이 실제로 폭·높이를 가지는가 | 느립니다 (`check_render` 를 또 돌림) |

**㉮ 를 권합니다.** `div` 수만 세는 것(아무 쪽이나 통과)과
크롬으로 재는 것(느림) 사이에서, **자료가 심긴 자리**를 세는
것이 속이기 어렵고 빠릅니다.

이 물음은 **계약과 따로**입니다. 검수 뷰만의 일이 아니라
앞으로 CSS 로 그림을 그리는 쪽마다 걸립니다.

→ 계약이 필요한 것은 **일곱이 아니라 여섯**입니다.

### 더 나쁜 것 — 지금은 조용합니다

판정 #161 이 잰 쪽수는 **450**, 제 로컬은 **451** 입니다.
차이 한 쪽이 검수 뷰입니다.

`build.py` 가 `build_review.main()` 을 **인자 없이** 부르고,
`main()` 은 `모의 = '--모의' in sys.argv` 를 봅니다. 그러니
진짜 스냅샷만 찾고, 저장소에는 모의 자료만 있어
**쪽이 깃허브에서 영영 안 만들어집니다.**

즉 지금은 **판정이 그 쪽을 한 번도 안 봤습니다.** 통과였던 것이
「괜찮다」가 아니라 「안 쟀다」였습니다. 이것을 고쳐 쪽이 생기면
위 일곱이 한꺼번에 터집니다. 그래서 **계약이 먼저**입니다.

## 1. 쪽은 스스로 말합니다 — 주소로 가리지 않습니다

### 겪은 일

`check_mobile.py` 의 `쪽갈래()` 는 **주소 꼴로** 가립니다.
`point/jeonbuk/...` → `point/jeonbuk`. 표본을 뽑을 때는 이것으로
되지만, **무엇을 요구할지 가리는 데 쓰면 안 됩니다.**
새 쪽을 만들 때마다 검사기 서넛이 오해합니다.

### 그래서 — 쪽 안에 박습니다

```html
<meta name="badagaja:쪽종류" content="public">
```

세 값만 씁니다. 네 번째를 쓰려면 이 문서를 먼저 고칩니다.

| 값 | 무엇인가 | 보기 |
|---|---|---|
| `public` | 손님이 보는 쪽 | 450쪽 전부 |
| `internal-admin` | 운영자가 쓰는 쪽 (고칠 수 있음) | 아직 없음 |
| `internal-review` | 검수용 **읽기 전용** 쪽 | `/stats-review/` |

### 어디서 박나 — 한 곳입니다

`engine/template.py` 의 틀 한 곳에서 박습니다. 기본값은
`public` 입니다. 쪽마다 손으로 적지 않습니다.

```python
값들.setdefault('쪽종류', 'public')
```

**기본값이 `public` 인 까닭** — 안전한 쪽으로 틀립니다.
`public` 은 요구가 가장 많으므로, 실수로 기본값이 붙으면
검사기가 잡습니다. 거꾸로 기본값을 `internal` 로 두면
**실수가 조용히 통과**합니다.

### 없으면 — 못잼(4)입니다

틀을 안 거친 쪽이 있다는 뜻입니다. 통과로 내지 않습니다.

## 2. 갈래별 요구 — 「안 봄」을 쓰지 않습니다

★ **가장 중요한 결정입니다.**

갈래를 붙이면 「검사를 안 받는 쪽」이 생길 위험이 있습니다.
그것은 거짓 통과로 가는 길입니다. 그래서 **「안 봄」이라
적지 않고, 갈래마다 무엇을 보는지 적습니다.**

| 무엇 | `public` | `internal-admin` | `internal-review` |
|---|---|---|---|
| 설명·og 다섯·트위터 카드 | **필수** | **금지** | **금지** |
| canonical | **필수** | **금지** | **금지** |
| `noindex,nofollow` | **금지** | **필수** | **필수** |
| 사이트맵에 | **필수** | **금지** | **금지** |
| 보이는 것(사진·막대·표) | **필수** | **필수** | **필수** |
| 아이콘 선언 | **필수** | 안 요구 | 안 요구 |
| 들어갈 길(링크) | **필수** | **운영 차림표에서만** | **없어야 함** |
| 개인을 가릴 수 있는 것 | 금지 | 금지 | **금지(전수 수색)** |
| form·button·input·script | 됨 | 됨 | **하나도 금지** |
| 집계값이 자료와 맞는가 | — | — | **필수** |
| 제목·설명 길이 | **검사** | 안 요구 | 안 요구 |
| 옛 쪽 대비 | **검사** | 해당 없음 | 해당 없음 |

### 왜 「보이는 것」은 셋 다 필수인가

규칙 6-1 — 「사람은 눈으로 봅니다. 쪽에는 보이는 것이
있어야 합니다.」 **검수 쪽도 사람이 봅니다.** 숫자를 글로만
적으면 검수가 안 됩니다.

이 줄은 **셋 다 필수**로 둡니다. 갈래마다 예외를 만들지
않습니다. 다만 **「보이는 것」을 무엇으로 세는지**는 0절 ※※ 의
넷째 물음으로 따로 정합니다 — `<img>`/`<svg>` 만 세는 지금
정의가 CSS 로 그린 막대를 못 봅니다. 쪽을 고칠 일이 아니라
**세는 법**을 고칠 일입니다.

### 금지 항목이 요구만큼 중요합니다

`internal-*` 에 og 가 **없어야** 합니다. 있으면 공유했을 때
퍼집니다. 그러니 「요구 안 함」이 아니라 **「있으면 어김」**
입니다. canonical·사이트맵도 같습니다.

`internal-review` 에 `<script>` 가 하나라도 있으면 어김입니다.
이미 `check_review_view.py` 가 봅니다.

## 3. 거짓 통과를 막는 장치 넷

갈래를 붙이는 것 자체가 빠져나갈 구멍이 됩니다. 넷으로 막습니다.

### ㉠ `internal-*` 쪽수를 기준선으로 묶습니다

지금 기준선은 **0** 입니다(판정이 쟤 본 적 없으므로).
계약을 넣고 검수 뷰가 생기면 `internal-review` **1** 이 됩니다.
그 수가 늘면 **막습니다.** 늘려야 하면 사람이 받아들입니다.

이러면 「검사가 까다로우니 internal 로 돌려 버리자」가 막힙니다.

### ㉡ 갈래마다 **적어도 한 장**은 전수 검사를 받습니다

`check_mobile.볼쪽들()` 이 갈래마다 한 장을 뽑는 것과 같은 방식
입니다. 새 갈래가 생기면 검사 코드를 안 고쳐도 한 장이
검사를 받습니다.

### ㉢ 「금지」가 정말 막히는지 뮤테이션으로 잽니다

`tests/test_checkers.py` 에 더합니다.

| 망가뜨릴 것 | 잡아야 할 것 |
|---|---|
| `internal-review` 쪽에 og:title 을 넣는다 | 어김 |
| `internal-review` 쪽에서 noindex 를 뺀다 | 어김 |
| `public` 쪽에 `쪽종류=internal-review` 를 붙인다 | 어김(쪽수 기준선) |
| 틀에서 `쪽종류` 를 뺀다 | **못잼(4)** |
| `internal-review` 쪽을 사이트맵에 넣는다 | 어김 |

기억 「뮤테이션은 정말 망가뜨려야」 — 쪽을 진짜로 고쳐
돌립니다. 흉내만 내지 않습니다.

### ㉣ 갈래별 요구표를 **한 곳에** 둡니다

검사기 일곱이 각자 「이 쪽은 internal 이니 건너뛰자」를
적으면 일곱 군데가 어긋납니다. `engine/pagekind.py` 한 곳에
표를 두고 모두 그것을 읽습니다.

```python
def 쪽종류(글):
    """쪽이 말하는 갈래. 없으면 None (= 못잼)."""

def 요구하나(갈래, 항목):
    """갈래가 그 항목을 요구하는가 — 필수/금지/안요구"""
```

규칙 「숫자는 한 곳에서만」을 글이 아닌 **코드로** 지킵니다.

## 4. 하는 차례 — 다섯 걸음

| 걸음 | 무엇 | 어긋나면 |
|---|---|---|
| ① | `engine/pagekind.py` 와 요구표를 만듭니다 | — |
| ② | `template.py` 가 `쪽종류` 를 박습니다 (기본 `public`) | 450쪽에 meta 한 줄 늘어남 |
| ③ | `build_review.py` 가 `internal-review` 를 박습니다 | — |
| ④ | 검사기 일곱이 요구표를 읽게 고칩니다 | 이때 8가지가 통과로 바뀜 |
| ⑤ | 뮤테이션 다섯을 더합니다 | 덜 막혔으면 여기서 드러남 |

**①~③ 뒤에 돌려도 ④ 전에는 8가지가 그대로 실패합니다.**
그것이 맞습니다 — 쪽이 말하기만 해서는 아무것도 안 바뀝니다.

## 5. 「빌드가 모의 자료로 쪽을 만들까」 — 갈림길

계약과 별개로 정해야 하는 것입니다.

| | 갈래 A — 모의로도 만든다 | 갈래 B — 안 만든다 |
|---|---|---|
| 판정이 검수 뷰를 재나 | **잽니다** | 못 잽니다 |
| 운영 스냅샷 오기 전에 볼 수 있나 | **볼 수 있습니다** | 못 봅니다 |
| 쪽수 | 451 | 450 |
| 계약이 꼭 필요한가 | **필요** | 지금은 안 필요 |
| 위험 | 모의 숫자를 진짜로 오해 | 약속한 쪽이 없음 |

**A 를 권합니다.** B 는 기억 「약속한 것이 거기 있어야」에
걸립니다 — 쪽을 만들어 두고 아무도 못 보는 상태가 됩니다.
그리고 **판정이 안 재는 쪽이 저장소에 있는 것**이 가장 위험합니다.

A 로 가면 모의 숫자 오해를 막는 장치가 이미 있습니다 —
`check_review_view.py` ⑥ 이 「모의 자료로 그렸으면 그렇게
적혀 있을 것」을 봅니다.

## 6. 총감독께 올리는 판단 요청 셋

1. **갈래 이름 세 가지를 이대로 둘지.** (`public` /
   `internal-admin` / `internal-review`)
2. **`내부쪽수 기준선`을 쓸지.** 「검사가 까다로우니 internal 로
   돌려 버리자」를 막는 장치입니다. 쪽을 늘릴 때마다 사람이
   받아들여야 하는 번거로움이 생깁니다.
3. **5절의 A 로 갈지.** 모의 자료로도 쪽을 만들어 판정이
   재게 할지.
4. **「보이는 것」을 무엇으로 셀지** (0절 ※※ 의 ㉮·㉯·㉰).
   ㉮ 를 권합니다. 이것은 계약과 따로이고, 앞으로 CSS 로
   그림을 그리는 쪽마다 걸립니다.

승인 전에는 ①~⑤ 어느 걸음도 시작하지 않습니다.

## 7. 이 문서를 쓰며 제가 두 번 틀렸습니다

적어 둡니다. 같은 식으로 또 틀릴 것이기 때문입니다.

1. 「`check_photos` 가 **사진만** 센다」 — **틀렸습니다.**
   이미 `<svg>` 를 셉니다. **검사기를 읽어 보지 않고** 증상만
   보고 적었습니다.
2. 「그러면 막대를 `<svg>` 로 바꾸면 끝」 — **성급했습니다.**
   통과시킨 디자인 시안을 깨뜨리고, 검사를 통과하려고 태그를
   끼워 넣는 짓이 됩니다.

둘 다 **손으로 확인하기 전에 적은 것**입니다. 확인하는 데
명령 두 번이 들었습니다. 기억에 「거짓 양성부터 걷어내기 —
새 검사기가 잡으면 먼저 손으로 확인」이 있는데도 또 그랬습니다.

→ **설계안에 「검사기가 X 를 못 한다」고 적을 때는, 그
  검사기를 먼저 읽습니다.**
