# 최종 RC 검수 및 배포 승인 지시서 (2026-09-27 바깥 검수)

이 문서는 바깥 검수에서 받은 지시를 그대로 옮긴 것입니다.
**고치지 않습니다.** 진행 상황은 `engine/gate.py` 가 냅니다.

## 판정 규칙

계약·항목마다 반드시 넷 중 하나입니다.

```
PASS         실제 측정으로 조건을 모두 만족
FAIL         조건을 하나라도 위반
NOT_TESTED   검사하지 못했거나 측정에 실패
N.A.         해당 조건 자체가 없음
```

**NOT_TESTED 를 PASS 나 경고로 처리하지 않습니다.**

## 배포 승인 규칙

```
FAIL > 0           → NO-GO
NOT_TESTED > 0     → NO-GO
PASS + N.A. 만     → GO 후보
```

마지막에 반드시 자동 계산해 냅니다.

```
TOTAL = PASS + FAIL + NOT_TESTED + N.A.
```

이 식이 성립하지 않으면 **검수 체계 자체가 FAIL** 입니다.

## 바깥 검수가 특히 짚은 것

**「검수기가 뭔가를 찾았다」보다 「검수 결과 자체를 신뢰할 수 있는가」가
이번 단계의 핵심입니다.**

- 사람이 숫자를 읽고 판단하면 안 되고 **프로그램이 숫자를 검증**해야 합니다
- 260/416 은 「416쪽 검증 통과」가 아니라 「260쪽까지 문제 없음」입니다
- 「기존 사이트가 그러니 검사하지 않는다」가 되면 **옛 문제를 새 기준으로
  역수입**합니다 — 디자인 기준과 접근성 경고를 갈라야 합니다
- 「삭제 안 함」이 정책이 되면 안 됩니다 —
  **「허용목록에 없는 옛 파일은 삭제」**가 되어야 장기적으로 깨끗합니다
- 롤백은 「시간상 바로 전 파일」이 아니라
  **「검증을 통과한 release-ID」**로 돌아가야 합니다
- PASS 에도 **증거**를 붙입니다 (검사기·대상·측정값·시각·빌드 ID)
