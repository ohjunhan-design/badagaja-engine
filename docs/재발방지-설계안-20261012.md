# 오전 작업이 사라진 일 — 왜 생겼고 어떻게 막나

주인 지시 2026-10-12 — 「이런 문제 발생 안하게 **근본적인 방법** 찾아」

**이 문서는 설계안입니다. 검사기 코드는 한 줄도 쓰지 않았습니다.**
총감독 승인 전에는 만들지 않습니다.

---

## 0. 무슨 일이 있었나

주인께서 오늘 오전 7시대에 손수 고치신 것들이 **오후에 통째로 사라졌습니다.**

> 「오늘 오전에는 지피티가 제시한 초급 중급 고급 이렇게 이미지가 있고
>   별도의 페이지도 있었는데 **그게 사라졌어**」

조사해 보니 **쪽은 멀쩡했고 가는 길이 끊긴 것**이었습니다.

| 어디서 | 오전 | 복원 전 |
|---|---|---|
| 첫 쪽 | 링크 1 | **0** |
| 안내 허브 | 링크 1 | **0** |
| 어종 목록 | 링크 1 | 1 |

오늘 같은 일이 **두 번** 났습니다.

| 때 | 무엇이 사라졌나 |
|---|---|
| 18:27 → 18:30 (어제) | `stats.html` 이 옛 판으로 덮임 |
| 07:49 → 오후 | 단계 쪽 가는 길, 동호회 칸, 지도 손질 |

---

## 1. 뿌리 하나 — **저장소가 둘인데 서버는 하나입니다**

```
  D:\바다가자\badagaja-site        D:\바다가자\두번째도전
   (옛 저장소 · 손으로 만든 쪽)      (엔진 · 자료에서 만들어 냄)
        645쪽                            451쪽
          │                                │
          └──────────┐        ┌────────────┘
                     ▼        ▼
              badagaja.com (서버 하나)
                 나중에 올린 쪽이 이깁니다
```

주인께서는 **옛 저장소에서 고치셨습니다.** 거기가 열려 있었고,
쪽이 눈에 보이는 HTML 이라 고치기 쉽습니다. 그런데 엔진은 그 사실을
모릅니다. 다음 빌드가 자기 판으로 **조용히 덮습니다.**

**누구 잘못도 아닙니다.** 어디서 고쳐야 하는지 알 길이 없는 구조입니다.

---

## 2. 지금 막혀 있는 것 — **다시 재어 확인했습니다**

| 길 | 상태 | 근거 |
|---|---|---|
| 옛 저장소 `deploy.yml` | **막힘** | 원격 main 에 `79174b0` 적용 — `on: push` 제거, `if: ${{ false }}` |
| 옛 저장소 `deploy-cloud.yml` | **안 위험** | `cloud/**` 가 바뀔 때만, 그것도 **다른 서버**(badagaja.cloud) |
| 나머지 워크플로 다섯 | **안 위험** | FTP 낱말 0 · 자동 걸림 0 |
| 엔진 `deploy.yml` | 손으로만 | `workflow_dispatch` + 판정 통과 필수, 우회로 없음 |

★ 조사 중 제가 한 번 헛짚었습니다 — **로컬** 옛 저장소에 차단 커밋이
없어 「위험」이라 적었는데, **원격에는 있었습니다.** 로컬이 낡았을
뿐입니다. 로컬만 보고 판단하면 틀립니다.

즉 **자동으로 덮일 길은 지금 없습니다.** 남은 위험은 **사람이 손으로
옛 저장소 파일을 올리는 것**입니다.

---

## 3. 그런데 막는 것만으로는 모자랍니다

길을 막아도 **주인께서 옛 저장소에서 고치시는 일**은 그대로입니다.
그러면 이렇게 됩니다.

- 고친 것이 **운영에 안 올라갑니다** (막혀 있으니까)
- 또는 손으로 올렸다가 **다음 엔진 배포에 덮입니다**

어느 쪽이든 **일한 것이 없어집니다.** 그러니 막는 것 말고
**옮기는 길**과 **알아채는 장치**가 함께 있어야 합니다.

---

## 4. 제안 셋

### ㉠ 운영 대조 검사 — **덮기 전에 멈춥니다** (가장 큰 것)

배포 직전에 **운영에 있는데 새 빌드에 없는 것**을 찾아 멈춥니다.

```
  올리기 전
    ① 운영에서 표본 쪽을 받아옵니다 (첫 쪽·허브 등 20쪽쯤)
    ② 새 빌드의 같은 쪽과 **눈에 보이는 것**을 셉니다
         · 링크 주소 목록      · <h2> 제목 목록
         · 사진 주소 목록      · 단추 글자 목록
    ③ **운영에는 있는데 새 빌드에 없는 것**이 있으면 → 멈춤
    ④ 사람이 봅니다 — 「일부러 뺀 것」이면 받아들이고(기준선),
       「모르고 빠진 것」이면 고칩니다
```

오늘 사건에 넣어 보면 — 운영 첫 쪽에 `guide/fishing-levels.html` 이
있고 새 빌드에 없으므로 **덮기 전에 걸립니다.**

| | |
|---|---|
| **왜 이게 핵심인가** | 두 저장소를 하나로 합치지 않고도 사고를 잡습니다. 구조는 그대로 두고 **결과만** 봅니다 |
| 어디에 붙나 | `deploy.yml` 의 판정 단계 (업로드 **전**) |
| 드는 시간 | 표본 20쪽 순차 — 30초쯤. 전수 아님 |
| 거짓 경보 | 기준선 파일로 「이건 일부러 뺀 것」을 적어 둡니다 |
| ★ 승인 필요 | **신규 검사기 추가 금지** 지시가 있어 총감독 승인 전 만들지 않습니다 |

### ㉡ 옛 저장소에 경고 표지 — **들어오자마자 보이게**

`README.md` 맨 위와 `.github/` 안내에 적습니다.

```
  ⚠ 여기서 고친 것은 운영에 올라가지 않습니다
  
  운영 badagaja.com 은 **엔진 저장소**(badagaja-engine)가 만듭니다.
  이 저장소는 **멈춘 저장소**입니다. 여기서 고치면
    · 운영에 안 올라가거나
    · 손으로 올려도 다음 엔진 배포에 덮입니다
  
  고칠 곳 → D:\바다가자\두번째도전 (badagaja-engine)
  무엇을 어디서 고치는지는 아래 대조표를 보세요.
```

문서라 바로 쓸 수 있으나, **옛 저장소 푸시는 승인 후**입니다.

### ㉢ 이관 대조표 — **「이건 어디서 고치나」**

옛 사이트 파일을 고치려 할 때 **엔진 어디를 고쳐야 하는지** 적어 둡니다.

| 옛 저장소에서 고치던 것 | 엔진에서는 여기 |
|---|---|
| `index.html` 머리띠·로고 | `engine/build.py` 의 `LOGO_SVG`·`LOGO_BIG` |
| 꼬리 메뉴 항목 | `data/raw/site.json` 의 `꼬리메뉴` |
| 안내 허브 칸 | `engine/hubs_more.py` |
| 어종 쪽 도해 | `engine/art.py` |
| 쪽 전체 짜임 | `template/*.html` |
| 단계 쪽 | `template/fishing-levels.html` (손 쪽) |

오늘 복원하며 실제로 쓴 길입니다. 더 채워 가면 됩니다.

## 5. 곁들여 — 오늘 함께 드러난 작은 것 둘

### 손으로 만든 쪽은 **검사기 눈 밖**에 있습니다

`guide/fishing-levels.html` 은 틀을 안 거쳐 **판 지문이 없었습니다.**
`check_build_stamp` 가 잡아 줘서 알았고, `template.손쪽에판새기기()`
를 만들어 고쳤습니다(커밋 `b5e4570`).

**앞으로 손 쪽을 더 만들면 같은 일이 납니다.** 틀을 안 거치는 쪽은
반드시 그 함수를 지나가게 합니다.

### 같은 키가 두 번 있으면 **틀린 쪽이 이깁니다**

`site.json` 의 `_받는곳까닭` 이 두 번 있었고, json 파서는 뒤엣것만
남깁니다. 그래서 **사실과 다른 옛 설명**(「지금은 메일입니다」)이
이기고 있었습니다. 고쳤습니다(커밋 `1d2dd2c`).

`data/raw` 의 다른 json 15개는 전수로 재어 **중복 0** 입니다.
검사로 옮길 수 있으나, 이것도 **신규 검사라 승인 대상**입니다.

「사람이 안 보면 그냥 덮입니다」가 그대로입니다.
